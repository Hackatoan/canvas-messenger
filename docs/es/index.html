Empezar

Carga la extensión, conéctate a Canvas y comienza a chatear.

Instalar la extensión

Firefox: descarga el .xpi de la última versión y ábrelo en Firefox para instalarlo con un solo clic. Chrome: descarga canvas-messenger-chrome.zip, descomprímelo y carga la carpeta en chrome://extensions (activa el modo de desarrollador → Cargar descomprimida).

Conecta tu cuenta de Canvas

Abre la extensión y sigue la configuración del token para vincular tu perfil de Canvas y que tus compañeros puedan encontrarte.

Abre cualquier curso de Canvas

El panel de mensajería aparece sobre Canvas. Inicia un mensaje directo, crea un grupo o entra al canal de la clase.

Código abierto y autohospedable

Tres repositorios componen todo el sistema — todos públicos.

🧩

canvas-messenger

La extensión para Chrome/Firefox — la interfaz de usuario inyectada en Canvas.

📡

cm-relay

API REST para registro, tokens de autenticación, invitaciones y retransmisión de mensajes.

🔗

cm-signaling

Servidor de señalización WebRTC que gestiona las conexiones peer-to-peer.

Preguntas frecuentes

La versión corta.

¿Es gratis?

Sí — gratis y de código abierto bajo la licencia del repositorio. Si te ahorra dolores de cabeza con los chats de grupo, puedes buy me a coffee.

¿Funciona en Chrome y Firefox?

Ambos. Los scripts de compilación generan el manifiesto correcto para cada navegador.

¿Necesito mi propio servidor?

No — para usar Canvas Messenger simplemente, instala la extensión y se conectará al backend alojado de forma predeterminada. Solo necesitas tu propio servidor si quieres autohospedar todo el stack: los servidores de relay y señalización son de código abierto y compatibles con contenedores (imágenes ghcr.io + Dockerfiles), por lo que puedes ejecutarlos tú mismo y apuntar la extensión a tus propios endpoints.

¿Es un producto oficial de Canvas?

No. Canvas Messenger es una extensión independiente creada por la comunidad. No está afiliada ni respaldada por Instructure. Canvas es una marca comercial de Instructure, Inc.

¿Dónde están mis datos?

Los mensajes viajan de igual a igual (peer-to-peer) mediante WebRTC siempre que es posible; el relay gestiona el registro, las invitaciones y la entrega. Autohospeda el backend para mantener todo en una infraestructura que controles.
